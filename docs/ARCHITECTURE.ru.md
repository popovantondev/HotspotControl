# Архитектура

`HotspotControl.Core` содержит независимые от языка контракты, проверку ввода, последовательное выполнение операций и правила повторов. `HotspotControl.Windows` связывает API мобильной точки доступа Windows с этими контрактами и преобразует результаты. `HotspotControl.Localization` сопоставляет коды результатов и ключи интерфейса с немецким, русским и английским текстом. `HotspotControl.Presentation` реализует общие представления WPF. `HotspotControl.App` связывает их с сетевыми функциями Windows, настройками, активацией единственного экземпляра и системным треем.

`HotspotControl.Preview` использует те же представления с демонстрационным сервисом в памяти. Он не ссылается на производственные проекты Windows/App и не обращается к настоящим сетевым параметрам или настройкам пользователя. `HotspotControl.Probe` только читает диагностическое состояние.

Операции Windows выполняются последовательно. По истечении тайм-аута ожидание интерфейса завершается, но операция Windows может продолжаться; запоздалый результат не выдаётся за новый успех. Текущее состояние уточняется новым запросом. Ручные команды отменяют ожидающие повторы автовключения. Координатор экземпляра для текущего пользователя восстанавливает существующее окно при повторном запуске программы.

Настройки сохраняют параметр автовключения из версии 0.2.0, добавляют язык и безопасно отклоняют повреждённые схемы или схемы будущих версий. При сохранении сетевой пароль передаётся Windows и не сохраняется в файле настроек приложения. Ярлык запуска Windows создаётся только для текущего пользователя.

`Run-Checks.ps1` собирает проект и запускает проверки поведения без изменения сети. Проверки превью и рендеры используют вымышленные данные. Интеграционные тесты, меняющие настоящую точку доступа, проводятся только в отдельно согласованное время. Старые нумерованные документы описывают проектирование и проверки прежней версии 0.2.0, а не текущие заявления для версии 0.3.0.
